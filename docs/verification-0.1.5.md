# 0.1.5 이미지 너비와 편집 중 PDF 대기

- 일자: 2026-10-08. 이미지 수정 `1a646dd`, 렌더 준비 개선 `dd9b618`, 태그 `v0.1.5`.
- [릴리스 검사](https://github.com/luftaquila/qollab/actions/runs/37647880947): 전체 성공. 같은 커밋의 중복 main 실행은 취소했다.

## 원인과 변경

- Crepe의 이미지 드래그는 `ratio`를 바꿨지만 Quarto 저장은 `width`만 사용했다. 반대로 속성 창의 너비는 Crepe의 이미지 화면에 적용되지 않았다.
- 이미지 NodeView가 `width`를 기준으로 표시하고 드래그 완료 시 백분율 너비를 저장한다. 숫자 입력·드래그·협업·개인 undo·PDF가 같은 값을 사용한다. 기존 ratio는 저장 시 너비에 반영한다. 캡션·대체 텍스트·그림 ID·정렬은 유지한다.
- 이전 렌더러는 마지막 빌드 이후 빈 컨테이너가 30초 뒤 사라지면 새로 준비하지 않았다. 따라서 연속 입력 때의 0.1.4 측정값은 잠시 쉬었다가 편집하는 상황을 설명하지 못했다.
- 인증된 편집자 연결이 열려 있는 동안 빈 컨테이너를 갱신한다. 각 컨테이너는 30초 후 폐기하며 문서를 전달한 컨테이너는 재사용하지 않는다. 접속 상태는 인증된 관리자 API로 확인하고 앱 응답 중단 시 15초 안에 갱신이 멈춘다. 뷰어만 접속한 경우에는 갱신하지 않는다.
- 참조 캐시 기한은 5분에서 1시간으로 늘렸다. 메모리 16MiB·작업별 1MiB 제한, 프로젝트·문서 세대 분리, preamble 확인, 실패 시 새로 빌드하는 동작은 유지한다.

## 자동 검사

- 로컬과 CI의 TypeScript/Vue 검사와 빌드, Vitest 37개, Python 3개, Chromium 6개 통과.
- 두 브라우저에서 이미지 80% → 드래그 40% → undo/redo → 속성 25% → 다시 열기를 검사했다. 붙여넣기·드롭·업로드 실패·교체·복원 검사도 통과했다.
- 렌더러 activity API 인증, 뷰어 제외, 편집자 연결 종료, 빈 컨테이너 만료 후 갱신과 최종 정리를 검사했다.
- 네이티브 Docker AMD64·ARM64의 실제 PDF에서 너비 20%와 40%의 이미지 사각형을 Poppler로 추출했다. 두 아키텍처 모두 **89pt → 178pt**, 정확히 두 배였다. [측정](evidence/0.1.5/pdf-width-ci.json).
- 양쪽 아키텍처에서 참조 캐시·목차/페이지/문헌 참조 변경·캐시 손상 복구·네트워크/자격증명 격리·timeout·프로덕션 앱 실행·백업 복원을 통과했다. [AMD64](evidence/0.1.5/deployment-amd64.json), [ARM64](evidence/0.1.5/deployment-arm64.json).
- 로컬 브라우저 검사는 임시 시험 DB를 사용했다. 운영 DB나 실제 사용자 문서는 수정하지 않았다. 시험 DB와 연결은 종료 후 제거했다. 로컬 Podman 설치·상시 앱 실행은 복원하지 않았다.

## 실제 서버 측정

같은 Linux ARM64 서버, CPU 1개·메모리 2GiB, 자동 빌드 대기 750ms에서 같은 시험 문서를 사용한다. 한글·표·수식·PNG가 있는 한 페이지 문서다. 편집 화면을 열어 둔 채 각 입력 전에 **40초 기다린다**. 한 글자 입력부터 새 build ID의 PDF 응답과 실제 canvas 표시까지 측정한다.

| 입력 → 새 PDF 표시 | 0.1.4 | 0.1.5 |
|---|---:|---:|
| 1회 | 8.941초 | 5.879초 |
| 2회 | 7.897초 | 5.963초 |
| 3회 | 8.095초 | 6.447초 |
| 중앙값 | 8.095초 | 5.963초 |

- 같은 조건의 중앙값은 약 26% 감소했다. 저장 확인은 128–401ms였다. 이전 세 번은 모두 준비된 컨테이너가 없었다.
- 관리자를 재시작하고 편집 화면에서 40초 기다린 뒤 참조 캐시가 없는 첫 수정은 별도로 **8.213초**였다. 위 세 번은 그 다음 측정이다. 앱 진입 직후의 준비되지 않은 첫 빌드를 이 수치로 보장하지 않는다.
- 브라우저 오류 0개. [변경 전](evidence/0.1.5/latency-before.json), [변경 후](evidence/0.1.5/latency-after.json), [작업 단계 변경 전](evidence/0.1.5/worker-before.json)·[변경 후](evidence/0.1.5/worker-after.json).
- 변경 후 네 번 모두 입력 전에 빈 컨테이너가 준비되어 있었다. 일반 수정 세 번은 참조 재사용과 XeTeX 1회를 확인했다. 한글 문서에 입력한 글자도 생성 PDF 텍스트에서 확인했다.

## 실제 서버 이미지 확인

| 동작 | 저장된 너비 | PDF 그림 너비 | 편집기 그림 너비 |
|---|---:|---:|---:|
| 속성 입력 | 80% | 356pt | 407.36px |
| 드래그 | 40% | 178pt | 203.67px |
| 속성 입력 | 25% | 111pt | 127.30px |

- 두 브라우저의 너비가 일치했고 새로고침 후에도 25%가 유지됐다. 각 단계에서 새 PDF를 다운로드해 실제 그림 사각형을 추출했다. Poppler 좌표는 정수 반올림 값이다. 각 변경의 새 미리보기는 5.840–6.022초에 표시됐다.
- [측정 기록](evidence/0.1.5/image-width-live.json), [편집기와 PDF 화면](evidence/0.1.5/preview.png), [PDF 페이지](evidence/0.1.5/pdf-25-percent.png). 한글·표·수식·그림을 직접 열어 확인했다.

## 작업 수명과 정리

- 실제 빈 작업 Pod에 `.qmd`가 없고 UID 10001이며 서비스 계정 토큰이 없는 것을 확인했다. 읽기 전용 루트·capability 제거·CPU 1·메모리 2GiB 제한도 유지된다.
- 진행 중 빌드 취소 후 사용한 Pod는 5.044초 안에 사라졌고 마지막 정상 PDF가 유지됐다. [수명주기 기록](evidence/0.1.5/lifecycle.json).
- 시험 브라우저를 닫은 뒤에도 서비스의 다른 인증된 편집자 연결이 남아 있어 빈 Pod 1개가 유지됐다. 실제 서비스에서 모든 편집자가 없는 경우의 마지막 Pod 만료는 이번에 재검증하지 않았다. 자동 검사에서는 갱신 중단 후 빈 작업이 모두 제거되는 것을 확인했다.
- 실서비스 검증은 별도의 임시 계정·세션·프로젝트에서 수행했다. 해당 시험 데이터와 세션, 로컬 시험 서버·DB 연결을 제거했다. 사용자 문서는 수정하지 않았다.

## 성능 범위

- 앱 셸과 편집기/PDF 분리 로딩, Vue·Yjs 단일 런타임 검사를 통과했다. [로컬 번들 크기](evidence/0.1.5/bundle-local.json), 20KiB 문서 입력·전환·heap [로컬](evidence/0.1.5/performance-local.json)·[CI](evidence/0.1.5/performance-ci.json). 로컬 검사의 DB는 SSH로 연결한 임시 PostgreSQL이며 실제 서비스 PDF 응답 측정과 별개다.
- 첫 빌드·관리자 재시작·캐시 만료·문서 세대 변경에는 참조 정보를 새로 만든다. 문서 전체를 처리하는 Quarto 실행은 남아 있으므로 즉시 미리보기는 아니다. 참조나 페이지가 바뀌면 여러 차례 조판할 수 있다.
- 빈 컨테이너 교체 순간, 서버 부하와 다른 문서의 빌드 대기는 추가 시간을 만들 수 있다. 복잡한 대형 문서나 다중 프로젝트 부하의 수치를 일반화하지 않는다.

기존 `.env`의 `APP_IMAGE`, `RENDER_IMAGE`를 [고정 이미지](versions.env)로 갱신하고 실행한다. Google 설정과 기존 볼륨은 유지한다.

```sh
docker compose pull
docker compose up -d
# Rootless Podman
podman compose -f compose.yaml -f compose.podman.yaml up -d
```

운영 서버는 같은 이미지 digest를 사용한다. 배포 전 DB와 파일을 함께 백업했고 배포 후 HTTPS·앱·관리자 상태를 확인했다. 실제 Google 계정 로그인 재검증은 아니다. 새 편집기를 사용하려면 열려 있던 브라우저를 새로고침한다.
